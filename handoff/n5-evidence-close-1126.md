### 2.1 实际起止：约 13:40:41 – 13:46:34（+08）

三个独立读数互相咬合：

| 读数 | 值 | 出处 |
|---|---|---|
| 账号最后一次登录 | `m7audit`（userId 9002）登录成功 **2026-11-25 13:40:41.522397** | `system_login_log` id **71**（`log_type=100`、`result=0`、`user_ip=127.0.0.1`），n5rd 库，今日只读查询 |

| 录屏内部时长 | **349.320 s = 5:49.320** | WebM `Info > Duration`（TimecodeScale = 1 ms） |

**推算口径**：以文件 mtime 作末次写入时刻、以 `Duration` 作时长，录制起点 ≈ `13:46:34.532 − 349.320 s` = **13:40:45.212**；与最后一次登录 `13:40:41.522` 相差约 **3.7 秒**，即「登录 → 开录」的合理延迟。→ 被录下的活动窗口 ≈ **13:40:41 – 13:46:34**。

**必须一起写清的限定**（不写就是过度声称）：

1. **无绝对时刻元素**：该 WebM 的 `Info` 段**没有 `DateUTC`**，内部不含录制日期；上面的绝对时刻完全来自文件系统 mtime。
2. **文件不是浏览器直出**：`MuxingApp` / `WritingApp` 均为 **`Lavf61.1.100`**（ffmpeg），而 Chrome `MediaRecorder` 直出的 muxing app 为 `Chrome`。说明这份正式录屏**经过 ffmpeg 重封装或转码**；mtime 可能是**那次封装/落盘**的时刻而非录制停止时刻，整段窗口会随之整体平移。预定的采集工具是 Game Bar（直出 mp4），而正式件是 WebM，**中间这一步转换目前无记录**，建议补一句「谁、何时、用什么命令转的」。
3. **账号 ≠ 人**：`system_login_log` 只记账号。主持人的取数/预检脚本同样用 `m7audit`（11-25 当日该账号登录成功 **14 次**，自 07:37:30 起，末次即 13:40:41），因此**不能由登录行判定「这是读者本人登录」**。
4. **不是 `date -Is`**：记录头要的是两头时刻，本推算法给出的是「约」，不能顶替 `date -Is`，也不能保证与主持人纸面记的一致。
