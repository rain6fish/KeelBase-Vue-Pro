## 2. Guard semantics, exactly as implemented

These three mechanisms are often summarized as "no pushing during work hours". They are not the same thing.

### 2.1 Working-hours definition (`nonworking-calendar.cjs`)

- Fixed `+0800`, independent of the machine's local timezone.
- Working hours are **05:00–19:00**; evening mapping targets 19:00 → next day 03:00.
- A working day is Monday–Friday, **minus** `holidays`, **plus** `workdays` (make-up Saturdays/Sundays), read from `KeelBase-Private/.githooks/holiday-calendar.json`.
- **2026-11-26 (Thursday) is not in either list ⇒ it is a working day.** Today's cutoff is 19:00 sharp.

### 2.2 `pre-push` (installed in all four repositories)

The hook does **not** check the clock on its own. It blocks only when the marker file exists **and** the current moment is working hours:

```
<git-common-dir>/NONWORKING_PUSH_BLOCK      # written by post-commit on a working-hours commit
```

- Marker present + working hours ⇒ `push` exits 1 with the guard message.
- Marker present + non-working ⇒ the marker is **deleted** and the push proceeds.
- No marker ⇒ the push proceeds, whatever the hour.
- Escape hatch: `SKIP_NONWORKING_PUSH_GUARD=1`. The nightly task's own rules forbid using it for scheduled releases.

Current marker state (all written today by working-hours commits):

| Repository | Marker |
|---|---|
| `KeelBase4J` | present (13:02) |
| `keelbase-contract` | present (13:12) |
| `KeelBase-Vue-Pro` | present (13:24) |
| `KeelBase` | present (13:23) |

Consequence: **a push attempted before 19:00 tonight is blocked in every repository**; a push after 19:00 is allowed and clears the marker.

### 2.3 Release-window lock (`push-all-repos.sh`)

`RELEASE_LOCK` = `D:/Rain6fish/release-window.lock`. While it exists, the nightly script does **not** push, fast-forward or verify `keelbase-contract*`. It is not a git hook, so a manual `git push` in the contract repository is **not** stopped by it.
