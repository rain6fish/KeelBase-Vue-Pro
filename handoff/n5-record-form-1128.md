# 下一场验收的记录形态 —— 一页建议（2026-11-26，供 11-28 周会）

> **性质**：建议稿。**不改** N5 已有的裁定与材料，**不动**产品码 / 判据 / 证据原件；未提交、未 push。
> **起因**：N5 2026-11-25 场次暴露的不是「纸不好」，而是「纸只解决了不可伪造，没解决写全与可核」。本页给一个能在不动产品的前提下，让区间、起止、零求助、归属变成机器可核字段的记录形态。

---

## 0. 一句话

**把「记录纸」从纸换成一份由读者自己填、填完即封存、带哈希的电子记录；对象纸、起止、零求助日志都变成同一次封存里的字段。** 不变的是三条取证属性：主持人拿不到可改原件、读者书写独立、事后可验证未被改动。

## 1. 要保住的三件事（换成电子件后仍须成立）

| 属性 | 纸质靠什么 | 电子版靠什么 |
|---|---|---|
| 读者独立书写 | 读者自己手写、当场交回，主持人无副本 | 读者在自己的会话里填（自带设备或当场新建的独立浏览器 profile），填完只读，主持人那台机器不参与 |
| 不可事后改 | 纸上的字改不了 | 封存时算 `sha256`，写进独立清单；清单本身对外锚定（见 §2.4） |
| 可核可对照 | 纸与屏幕肉眼对 | 区间、对象、起止直接取自同一份结构化文件，不再经过誊录 |

## 2. 记录形态（四件，缺一不可）

### 2.1 读者申请书 —— 读者自己填的结构化记录

- 一份 `reader-sheet.md`（或最小版用 Markdown 表单），读者在**自己**的浏览器/编辑器里逐格填：两次检索的**对象、主键、起止区间（逐字抄屏幕）**、六问、导出文件名、第二入口三项。
- 填完即转只读（`attrib +R` 或另一份 `-final` 副本），**不在主持人机器上编辑**。
- 关键收益：区间不再靠誊录。11-25 的「纸上值 vs 屏幕值不一致」在这一形态下**不会发生**——记录纸上的区间就是读者当场抄的屏幕值。

### 2.2 会话封条 —— 起止与身份一次性落盘

开场与收场各跑一次只读小脚本（放 `handoff/` 外的工具目录，不进产品码），写入 `seal.json`：

```
{ sessionId, startUtc, endUtc, operator, readerCode,
  appHead, jarSha256, uiIndexSha256,
  artifacts: [ {path, bytes, sha256} … ] }
```

- 起止来自脚本自己的时钟，**不再依赖主持人手记 `date -Is`**。
- 收场时把 4 份 CSV、录屏、读者申请书一并纳入 `artifacts`，取代手工维护的 `SHA256SUMS`。
- 这一条直接把 N5 的「实际起止」缺口变成机器字段。

### 2.3 零求助日志 —— 写「0 次」也要有动作

- 主持人开一个 append-only 的 `question-log.md`，**每一次提问按一下热键追加一行**（时刻、性质、读者原话、回答）。
- 收场由读者在末行签一行：「本场主持人共回答 N 次，其中内容性 M 次」；N=0 时也必须写并签。
- 机器能做的只是「保证日志存在且未被改」；**有没有发生求助仍只能人证**——这一点不要指望工具替掉，只需让「零求助」从「没记」变成「记了 0」。

### 2.4 对外锚定 —— 让封条不可悄悄重做

- 收场后把 `seal.json` 的哈希写进一处场外记录：一次 commit（可推公开仓）、`gitee` 发布说明，或第三方可信时间戳（RFC 3161 / 联合信任 TSA）。
- 目的是：日后任何一方都无法把整包证据重做一份再声称是原件。

## 3. 与 N5 五个缺口的一一对应

| N5 缺口 | 本形态下 | 还缺什么 |
|---|---|---|
| 截图 | 读者申请书里附每步截图（读者自己按、自己存） | 仍靠读者愿意按；但至少归属清楚 |
| 签名件 | 读者在申请书末行签，扫描/拍照入包 | 签名本身仍只能人做 |
| 零求助记录 | `question-log.md` + 读者末行确认 | **零求助事实仍只能人证**（见 §2.3） |
| 实际起止 | `seal.json` 的 `startUtc/endUtc` | 无（机器字段） |
| 区间纸张值 | 申请书里的区间 = 屏幕值，无誊录环节 | 无（誊录层消失） |

## 4. 两个版本，按 11-28 能接受的成本选

| | **最小版**（下周即可用） | **完整版** |
|---|---|---|
| 内容 | 电子读者申请书（只读封存）+ 屏幕常驻时钟 + `question-log.md` 显式记 0 | 再加 `seal.json` 脚本、`artifacts` 自动哈希、对外锚定 |
| 工作量 | 半天（写模板 + 走一遍） | 1–2 天（脚本 + 试跑一场） |
| 依赖 | 无 | Node（本机已有）；对外锚定需一次 push 或 TSA 账号 |
| 能消掉的缺口 | 区间不一致、零求助「没记」 | 再加起止、证据清单手工维护 |

**建议**：11-28 先定最小版，下一场就用；完整版等下一轮再上。理由是最小版没有新依赖、不碰产品码，却正好覆盖这次吵得最凶的两项（区间、零求助）。

## 5. 这套东西管不到的

- **证据上限仍是 E3**：没有可追溯的独立真人批准人，是种子/数据模型问题，换记录形态一点也抬不动。
- **主持人 = 开发者**这一偏差仍在；电子记录只能保证「读者写的东西没被改」，保证不了「主持人没在旁边解释」。
- 录屏的转换环节（11-25 正式件由 ffmpeg 封装、无 `DateUTC`）需要在完整版里堵掉：**采集工具直出什么就存什么**，不做重封装。
