## 归属判定与动作选择理由

**判定：受治理的宿主动作，留在审计链。** 连通测试由管理员经 `/ai1/mcp/test` 触发
（`Ai1McpController.java:94-100`，权限 `ai1:mcp:test`），会带配置里的凭据拨向外部 MCP 端点并完成
`initialize + tools/list`（`Ai1McpClientTool.java:159-193`）。它改名换不动审计价值的那些事实——谁、
对哪条 MCP、拨向哪个 host、通没通、多久、失败类别——因此不按「纯运维诊断」移出链，而是按 2026-11-21
CTO 裁定的过渡要求执行：先删自造词、用既有动作记录并注明。

**为什么是 `analyze`。** v4 的 `action` 是 15 值闭枚举：
`chat, tool_call, navigate, error, login, plan, analyze, knowledge, delegate, tool_confirmation,
flow_node, content_blocked, effect_revoke, audit_review, claim_release`。逐个排除后剩下 `analyze`：

- `tool_call`：契约给它的 `outcome` 是工具结局词表，而连通测试不运行任何工具；且非工具行不得带
  `tool`，用 `tool_call` 加 `tool=null` 会把「没有工具」写成一次工具调用。
- `error`：只覆盖失败的一半，成功的那一半没有动作词，按它筛选会漏。
- `login` / `navigate` / `knowledge` / `delegate` / `flow_node` / `content_blocked` /
  `tool_confirmation` / `effect_revoke` / `audit_review` / `claim_release` / `chat` / `plan`：
  语义分别是登录、导航、知识检索、委托、流程节点、内容拦截、确认裁决、撤销、复核回执、占位释放、
  对话与规划，均不描述一次端点探测。
- `analyze`：一次诊断性动作，既不是工具调用、也不是写。它是语义最近的既有词；词表若将来为探测添了
  自己的词，只需改这一个常量。
