# 审计按业务对象检索 —— 设计与第一片

> English: [KEELBASE-AUDIT-SEARCH.md](KEELBASE-AUDIT-SEARCH.md)

这是 2026-11-07 周计划任务 **U1** 背后的设计：审计人员按**业务对象与时间区间**检索 AI 审计轨，并把六问
导出成一份**不含内部名**的 CSV。本文写清楚第一片做了什么、刻意不做什么，以及那条能去掉主要上界的运行时
读面变更。

## 1. 审计人员问什么，今天那几条面答什么

问题是：**「客户 #9005 上周发生过什么」**。控制台已经在读的几条面，各答其中一块：

| 面 | 收 | 答 |
|---|---|---|
| `GET /audit/logs` | `userId`、`since`、`isError`、`limit`、`offset` | 审计行，最新在前：谁、何时、动作、工具、结局、授权依据 |
| `GET /ai/tool-effects` | `userId`、`conversationId`、`page`、`limit` | 写入台账：工具、`resultType`、`resultId`、`executionId`、前后快照 |
| `GET /ai/confirmations` | `page`、`limit` | 被扣下 / 被拒的提议：工具，以及它当时要用的参数 |
| `GET /admin-api/keelbase/record-names` | `refs=type:key,…` | 记录名，**服务端已掩码**，只答账本里出现过的引用 |

这个问题要的三样东西里，有两样**不在**审计面上：对象筛选，以及区间的**终点**。运行时**拒绝**它不施加的
筛选 —— 一个被接受却没被施加的筛选，回出来的是一份看着像筛过、其实没有的列表 —— 那个拒绝是对的。

## 2. 查询跑在哪，为什么

第一片把检索放在**控制台这一侧**，跑在上面那几条面上：

- `/audit/logs` 从 `since` 起按页读到它的 `offset` 上限，给出那些行；
- `/ai/tool-effects`（最新的几页，有上界）与 `/ai/confirmations`（最新一窗）把每一行的对象解析出来；
- `record-names` 补上业务名，且已经掩码。

没有新端点、没有新 wire 字段、不改契约。控制台在本地做联结与筛选，并且**说出它扫到了哪**——一句不说的
上界，会让「没有行」被读成「没有这件事」。

## 3. 对象：`(resultType, resultId)`，绝不按文本

对象按类型与业务主键判等。显示出来的文本（`客户 · #9005 · 万****`）是掩码过、翻译过的，不能当键用。
一行的对象来自**审计页已经在用的那条三路证据链**，次序如下：

1. **台账行** —— 一次真的写。审计行带 `executionId`（契约 v6）时精确配；不带时按「同一工具、五秒之内、
   恰好一个候选」。带了 `executionId` 却在窗口里找不到那一行时回 `null`，**不**退回去按工具与时间猜——
   那一猜正是把两条不同的执行摆到一起的路。
2. **确认记录** —— 被扣下或被拒的调用。同一工具，且离提议的写下时刻**或**裁决时刻五秒之内，恰好一个候选。
3. **行末自己记下的键**（`… · intended object #12`）—— 被闸门拦下的调用。种类取自工具自己的
   `resultType()` 声明，绝不从那句话里读。

三路都没有，就是运行时确实没记下这次调用落在哪条记录上；那一行**不**配上任何对象。

### 怎么指定对象

| 输入 | 挑出 |
|---|---|
| 类型 + 主键 | 恰好那一条记录 |
| 只给类型 | 这一类对象的全部行 |
| 只给主键 | 那一条记录，不论类型（类型未知的行也算——不知道它是哪一类，不等于它是另一条记录） |
| 都不给 | 区间里的全部行 |

类型下拉由控制台认得出的记录种类生成，再按消息表里**有没有业务词**（`keelbase.record.*`）过滤。加一个
词就多一种可查的对象，不必改第二份清单。

## 4. 区间

`since` 是审计面自己的参数。`until` 在**本地**施加，因为那条面没有终点；页面把这句话说出来。两端都含。
时刻读不出来的行**不在**任何区间里：一条没法定位的行配不上 `since`。

## 5. CSV

恰好六列，按审计人员提问的次序：

| # | 列 | 值 |
|---|---|---|
| 1 | 谁 | 调用方的姓名与账号 |
| 2 | 何时（带时区） | 这一行的时刻，按本地渲染并**带出偏移量** |
| 3 | 哪个业务对象 | 业务种类 + `#主键` + 掩码后的名字 |
| 4 | 改成什么（改前 → 改后） | 运行时记下的改前，以及改后记了什么、没记什么 |
| 5 | 谁确认 | 这一行**记下的**那道闸：无需确认 / 本人 / 第二人（配到裁决行时点名）/ 被拦下 |
| 6 | 结果 | 结局词以及它意味着什么 |

表头就是六问自己的标签；值由**页面渲染用的同一个 `sixOf`** 产出，故文件不会与屏幕漂开。缺答案时导出它
诚实的原文（`—`、`未记录 —— 这次调用没有写任何记录`、`第二人批准了 —— 这一行没有记下是谁`），**绝不**
留空——空单元格在导出的表里读起来像「没有这件事」。

转义按 RFC 4180：含逗号、双引号、回车或换行的字段加引号，内部双引号写两遍；行尾 CRLF。下载时带 UTF-8
BOM，免得 Excel 把中文列读成乱码。

**不含内部名。** 生成文件之前，每个表头、每一格都过一遍六问评分用的同一个 `leaksIn`（snake_case 标识符、
schema 字段名、UUID、整格就是结局码）。命中一处就**整份拒绝**导出。错误只说**是哪一问**，不回显那串
文本——否则「拒绝导出」这件事本身，就把内部名印到了屏幕上。

## 6. 上界，说出来

| 窗口 | 上限 | 为什么 |
|---|---|---|
| 审计行 | 1000（`200 × 5`） | `/audit/logs` 的 `offset` 上限就是 1000，那也是这条面能走到的深度 |
| 台账行 | 300（`100 × 3`） | 它是对象索引，从最新一页往回走 |
| 确认记录 | 100 | 最新一窗，给被扣下 / 被拒的调用用 |

页面报「扫描到的范围里命中 N 行」，碰到上限时明说。比审计扫描还早的区间，答案是**「没有覆盖」**，不是
一个空结果。

## 7. 去掉这个上界的那个变更 —— 已落到读面

`GET /audit/logs` 现在收 `until` 与对象（`objectType` + `objectId`），检索就是一次查询、不是对整段窗口的
扫描。那是对运行时**读面**的变更：TypeScript 参照实现早已有这两个筛选；**Java 运行时**在它的 `objectRange`
改动里收下它们（`AuditController` / `AuditService`，经台账解析：带该对的副作用给出它们的执行 id，**恰好**那些
执行的行就是答案）。运行时施加不了的筛选仍被拒绝 —— 半个对象过滤是 400，没有台账的部署答 503 而不是一个空页。
**没有新增契约字段**：端点的参数不属于冻结的行 schema，参照实现那一片也是在不碰它的前提下加的同两个参数。

页面对三个参数与 `since` 一并发送。旧运行时忽略不认识的查询参数，控制台自己的收窄照旧决定，故两种运行时下
答案一致、差别只在扫回来的行数。控制台的台账与确认窗口仍是有界的：它们供的是对象的**显示名**与被拦/被拒行的
证据，不是行选择。

## 8. 这一片由什么证明

`scripts/audit-query.test.mjs` 钉住三路证据（含「带了 `executionId` 却配不上就什么都不答，而不是猜」）、
指定对象的三种方式、区间的两端、恰好六列且列序固定、RFC 4180 转义、缺答案的记号，以及**反向可证**：
一格透出 `crm_customer` 或一个 UUID 时整份导出被拒，错误点名那一问、不点名那串名字。
`scripts/audit-chain-page.test.mjs` 仍钉着页面的渲染路径，`scripts/i18n-key-coverage.test.mjs` 钉着新标签
在中英两套里都在。
